第 4 课 · 20–30 分钟外加运行时间

建立 MVP 基线

把演示系统变成一套可重复的测量手段，然后把它暴露出的每一个失败都当作工程证据来看待。

重点阅读：OpenAI——评估最佳实践

今天的具体收获

本课的具体收获： 学完这节课，你会拿到脱敏版 Meridian Labs 系统一份全新的实时基线——而且能准确说清它证明了什么，更重要的是，它没能证明什么。

1 · 安全第一：使用隔离的演示环境

所有命令都要在演示目录里跑：

cd demo

所有命令都要在演示目录里跑，别跑到 `api` 去了。演示环境是完全独立的一套：服务名、端口、集合、工作区、数据目录全都单独一份，只读取演示专用的配置和那一个演示 API key 文件。密钥相关的环境文件，千万别打印出来，也别随便打开。

开始之前，先确认一遍：

  • Docker 正在运行。
  • 演示专用的 API key 文件确实存在，而且里面真的有一个 key。
  • 端口 `8000` 没有被生产项目占用。

2 · 运行基线流程

先做离线检查：

python3 eval.py verify
python3 test_scoring.py

启动隔离环境：

python3 setup_demo.py up

随时用这个命令查看状态：

python3 setup_demo.py status

现在为这套虚构语料库建立索引：

python3 setup_demo.py ingest

索引这一步不会很快——图索引和摘要索引都要调用 LLM，得留够时间。如果语料库已经建好索引、你也想保留它，那就仔细看文档里的选项再操作，千万别手一滑把生产数据重建了。

3 · 先测检索，再测答案

先只跑纯检索评估——完全跳过 LLM 评审：

python3 eval.py run \
  --mode retrieval \
  --workspace meridian_demo \
  --tag lesson-4-retrieval

这一步能让你清楚看到每个索引各自扛了多少活：

  • 只用向量检索
  • 向量加全文检索
  • 向量加全文加摘要检索
  • 全部索引，包括近似图匹配

先只测检索这一步——不走 LLM 评审，也就不花那份钱。这一步能让你清楚看到每个索引各自扛了多少活。

4 · 测量生成的答案

接下来，运行答案评估：

python3 eval.py run \
  --mode answer \
  --workspace meridian_demo \
  --tag lesson-4-answer

这一步会调用 `/api/v1/qa`，核对引用和必需关键词，再交给评审模型把每个答案判成 `correct`、`partial` 或 `incorrect` 三档，顺带把拒答率和延迟也一并测出来。

第一次这么做？先限制一下样本数量：

python3 eval.py run \
  --mode both \
  --workspace meridian_demo \
  --limit 10 \
  --tag lesson-4-smoke

5 · 像工程师一样读报告

报告会生成在这里：

demo/reports/

不说清楚定义就甩一个数字出来，没有意义。把这几项都记下来：

指标你的数值含义
检索覆盖率（并集）_____综合各个索引，找到了多少预期来源
严格准确率_____评审判定为 `correct`
来源命中率_____最终答案里引用了每一个预期来源
拒答准确率_____不可回答的问题被正确地拒答
幻觉率_____不可回答的问题却被强行作答
延迟 p50 / p95_____典型响应时间和慢尾响应时间

光甩一个数字出来、不说清楚它的定义，没有意义。把这几项都记下来：检索覆盖率、严格准确率、来源命中率、拒答准确率、幻觉率，还有 p50/p95 延迟。

6 · 练习：这是基线，还是夸大其词？

陈述 A：“在 65 个问题的 Meridian Labs 评估集上，用 `gpt-4o-mini`、topk 5、当前这个工作区跑出来，严格答案准确率是 70%。”这句话算得上是一个站得住脚的基线陈述吗？

陈述 B：“这个聊天机器人准确率是 70%。”写进技术报告里，这句话够格吗？

陈述 C：检索覆盖率很高，但严格答案准确率却很低，这时候你该去查哪里？

与课程使命的关系

QA 或法规团队拿到一个既解释不了、也复现不了的数字，其实什么都做不了。基线的作用就是让原型保持诚实——它把现在的优势、现在的短板都摆在台面上，也能告诉你下一次改动到底有没有真的起作用。

下一步行动

至少要把检索评估和答案评估都跑一遍。然后把这些发给我：

  1. 两个报告的标签。
  2. 检索覆盖率（并集）百分比。
  3. 严格答案准确率。
  4. 来源命中率。
  5. 拒答准确率与幻觉率。
  6. 你最想优先排查的一个失败案例，附上它的评审理由。

下一步：至少把检索评估和答案评估都跑一遍，然后把两个报告标签、几项关键指标，还有一个你最想优先排查的失败案例，发给我。

如果 Docker、索引、评审模型，或者任何一个指标你没弄明白，随时问我，不用自己瞎猜。 在我们把第 4 课标记完成之前，我会帮你一起把这份实时结果看懂。
