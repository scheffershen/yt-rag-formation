Jeux d’évaluation RAG fiables

Une check-list pratique pour mesurer un chatbot d’entreprise sans se raconter d’histoires.

Le tuple d’évaluation

Question + catégorie + sources attendues + faits requis + comportement attendu

Pour une question répondable, le système doit donner une réponse correcte, fondée sur les preuves. Pour une question sans réponse, il doit refuser de répondre.

Ce que teste un bon jeu d’évaluation

DimensionPourquoi c’est importantDémo Meridian

AcronymesRésoudre les termes de domaine et les abréviations.3 questions
Sans réponseMesurer si le système refuse de répondre plutôt que de récompenser une hallucination.6 questions

Règles de la référence

  1. Chaque source attendue doit être présente dans le corpus.
  2. Chaque fait requis doit apparaître littéralement dans une source attendue.
  3. Une question sans réponse ne doit avoir ni source attendue ni fait requis.
  4. Faites correspondre les sources récupérées par métadonnées, pas par un texte arbitraire dans un fragment.
  5. Gardez le jeu d’évaluation inchangé pendant la comparaison des changements du système.

Mauvaise mesure

Compter un résultat vectoriel comme une réussite simplement parce que le texte de son fragment mentionne l’identifiant du document attendu.

Meilleure mesure

Ne le compter comme une réussite que lorsque les métadonnées de source identifient le document attendu.

Limite de confiance

Un harnais d’évaluation peut se tromper tout en affichant un pourcentage à l’air pourtant confiant. Testez l’outil de notation lui-même avec des accents, des questions multi-sources, des renvois dans le corps du texte, des citations manquantes et des refus.
