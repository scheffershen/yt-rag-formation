延迟、成本与可观测性

用于本课工程决策的证据速查表。

一句话规则

一句话规则：平均延迟可能掩盖让系统在试点中不可用的慢尾延迟。

核心术语

术语含义
p50 和 p95中位数与慢尾延迟。两个都很重要，因为看起来很快的平均值可能掩盖让人头疼的异常值。p95 只有在 answer 模式下才会计算——纯检索模式只报告 p50。
成本驱动因素嵌入调用、图谱 LLM 调用、答案生成、评审调用，以及上下文大小。
唯一真正能调的旋钮--graph-topk（默认 20）——调低它，就是用 LightRAG 的图遍历深度换取延迟。没有办法在一次线上请求中把 LightRAG 整个关掉。
可观测性结构化的追踪、指标和日志，能说清楚发生了什么，同时不暴露密钥或文档文本。

证据卡

需求记录内容不要声称
基线命令、配置、观察到的结果——与第 4 课同一份 eval_set.yaml 基线。基线是一个目标。
改动一个假设或一次决策当同时改了好几件事时，你还能分清是什么造成了结果。
指标summary.answer.latency_p50_s/.latency_p95_s、summary.retrieval.latency_p50_s、answer.stats.total_context_chars/.graph_context_chars；密钥和原始敏感内容永远不要记入日志。单一指标能说明质量的全部情况。
安全性一个失败案例和一个回归案例一个流畅的回答就证明系统是可靠的。

证据卡：记录基线（跟第 4 课同一份 eval_set.yaml）、一次改动、指标和安全回归；不要把单一指标等同于整体质量。

本地命令

cd demo
python3 eval.py run --mode both --workspace meridian_demo --tag lesson-14-latency

一定要用 --mode both，别只用 --mode retrieval——纯检索汇总永远不会有 p95。
