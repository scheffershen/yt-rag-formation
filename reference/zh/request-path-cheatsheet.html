一个问题如何穿过 RAG 系统

一个问题如何穿过当前 `/api/v1/qa` RAG 系统。

核心路径

HTTP 请求 → 路由 → 服务 → 检索 → 组装上下文 → 引用 → 生成 → 响应

调用地图

阶段文件 / 函数职责
1. HTTP 入口routes/qa.py
ask_question()		接收 `QuestionRequest` 并传递给 QA 服务。
2. 编排qa_service.py
answer_question_internal()		校验输入，解析各项服务与配置，并协调整个请求。
3. 检索search.py搜索 Qdrant 分块、Qdrant 摘要、Meilisearch 以及 LightRAG。
4. 上下文utils.py
build_context()		在各通道之间分配预算，并保留能到达模型的条目。
5. 引用utils.py
sources_from_items()		根据通过上下文组装环节的证据构建来源列表。
6. 提示词utils.py
build_prompt()		指示模型使用上下文、引用来源，并拒答没有依据的内容。
7. 生成qa_service.py
completion.generate()		根据问题和组装好的上下文生成最终答案。
8. 响应models.py
AnswerResponse		返回答案、来源以及诊断统计信息。

调试时检查什么

  • 生成之前： 检查 `/api/v1/search` 和 `context_items_included`。
  • 引用阶段： 把 `sources` 和真正进入上下文的条目做对比。
  • 生成之后： 把答案同时与证据和预期答案做对比。
  • 排查延迟： 检查全部四个检索调用——尤其是 LightRAG——以及最后的生成调用。

调试时不要只看最终答案。先检查检索结果、实际进入上下文的项目、引用来源，再检查生成答案。
